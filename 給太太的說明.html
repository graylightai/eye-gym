目力練功房
你可以怎麼一起做

給第一次參與軟體專案、而且完全沒寫過程式的人

先講結論：你不需要學會寫程式。
你的 Mac 上會裝一個叫 Claude Code 的東西，打字交給它，判斷留給你。 你要練的是「說清楚想要什麼」和「看結果對不對」——這兩件事它做不到，只有你能做。

四顆按鈕，就是全部

打開 目力練功房 這個資料夾，裡面有幾個可以點兩下的檔案。你只會用到這四個。

⚙
設定這台電腦
只有第一次要點。它會檢查電腦上該有的東西都有沒有， 帶你登入 GitHub，然後告訴你缺什麼。全部打勾之後就不用再碰它了。
▶
開發
點兩下開始工作。它會先自動抓 Jessie 的最新版（這件事你不用管）， 然後打開瀏覽器。改完檔案存檔，回瀏覽器按 ⌘R 就看得到。
畫面上還會出現一個 QR code——用手機相機掃一下， 就能在真的手機上看你改的東西。這個很重要，因為這是給手機用的 app， 在電腦螢幕上看不準。
↑
送出給 Jessie 檢查
改好了，點兩下送出去。它會問你「改了什麼」，隨便寫一句就好 （例如「把開始按鈕改大一點」）。
送出不等於上線。Jessie 會看過，確認沒問題才按合併，那時候正式網站才換版。 所以你送出的東西不可能弄壞小孩在用的 app。
↺
還原
改壞了、越改越亂、不想要了——點兩下，全部回到正式網站上那一版。 這顆按鈕的存在就是為了讓你放膽亂改。
為什麼多一道檢查？不是不信任你，是因為正式網站就是小孩手機上那個 app—— 一按下去就換版了，沒有緩衝。多一道 diff 把關之後，你就可以完全不用擔心「我這樣改會不會害到她」， 放膽改就好。Jessie 自己改也走同一道流程，沒有例外。
手機上用 QR code 看的時候，「加到主畫面」和離線功能不會動， 因為那需要正式網址才有的安全連線。文字、顏色、關卡內容都看得到； 要測離線就等上線之後在正式網址上測。
第一次點這些檔案，Mac 可能會說「無法打開，因為來自未識別的開發者」。 在那個視窗按「取消」，然後到系統設定 → 隱私權與安全性，往下找到那一行，按「仍要打開」。只要做一次。

第一個月：一次只學一件事

不要想一步到位。下面四步，每一步都是真的在貢獻，而且每一步會讓下一步變簡單。

第 1 週

只是用它，然後記下問題

帶小孩每天用。你不碰任何檔案，但這一週的價值可能是全部裡面最高的—— 因為只有實際陪她用過的人，才知道哪裡不對勁。

拿手機備忘錄記，想到就寫：

  • 她在哪一關卡住、露出不耐煩的表情
  • 哪個字看不懂、哪個按鈕找不到
  • 哪裡太簡單讓她覺得無聊
  • 什麼時候她想自己再玩一次

不用寫得正式。「迷宮她每次都放棄」這樣就夠了。

第 2 週

改文字和數字

打開 js/content.js（用「文字編輯」或 VS Code 都行）。 這個檔案裡面全部都是你可以改的東西，而且每一行都有中文說明。

可以改的像是：

  • 每一關在首頁顯示的名字和說明
  • 視標大小的六個級距
  • 自動調難度的門檻（幾題、要多準、要多快）

流程永遠一樣：點「開發」→ 改 → 存檔 → 瀏覽器按 ⌘R 看 → 滿意就點「上線」。 不滿意就點「還原」，什麼事都沒發生過。

第 3–4 週

改顏色和字級

打開 css/tokens.css。整個 app 的顏色都在這一個檔案裡， 改一個地方，所有畫面會一起變。

每一個顏色都長這樣：--go:#148873;。#148873 就是顏色代碼。 在 Google 搜「顏色選擇器」隨便找一個，挑到喜歡的顏色、複製它的代碼貼上去就好。

檔案裡有兩組顏色：一組是淺色模式，一組是深色模式（手機設定深色主題時會用到）。 兩組都要改，不然其中一種模式會怪怪的。
第 2 個月起

用 Claude Code 做新東西

到這裡你已經很熟那個「改 → 看 → 上線」的循環了。接下來把想做的事說給 Claude Code 聽， 讓它寫，你負責看結果。這一節後面會講怎麼說。

哪些檔案是你的

檔案是什麼
js/content.js你的。文字、視標級距、難度門檻。每一行都有中文說明
css/tokens.css你的。全部的顏色、字體、圓角
css/app.css版面：首頁、報告、設定長什麼樣。可以改，但先問一聲
js/game-*.js五個關卡，一關一個檔案。兩個人同時改不同關卡不會打架
js/engine.js自動調難度的邏輯。先不要碰，改壞了小孩練的東西就不對了
js/state.js資料怎麼存。先不要碰
js/ui.js畫面怎麼運作。可以改，但先問一聲
唯一真正的禁區：js/engine.js 和 js/state.js。 前者決定視標大小怎麼自動調整，後者決定小孩的紀錄怎麼存。 這兩個改壞了，不會跳錯誤，但小孩練的東西會悄悄變成錯的——那比畫面壞掉嚴重得多。

怎麼跟 Claude Code 說話

這是整件事最關鍵的技能。重點不是用什麼術語，是說清楚你看到什麼、你想要什麼。

講現象，不要講解法

這樣說 ✓
「小孩玩迷宮的時候每次都放棄。我看她是手指擋住前面的路，看不到要往哪裡走。」
不要這樣說 ✗
「迷宮的 cellPx 改成 40。」

你不知道正確的解法是什麼——那是它的工作。但只有你看到她在皺眉頭。 把你看到的講出來，它會提出做法，你再判斷合不合理。

說清楚「改完之後應該變怎樣」

這樣說 ✓
「首頁那顆開始按鈕我想要更明顯，小孩第一次用的時候找了一下。」
太模糊 ✗
「首頁醜醜的。」

永遠要求它先讓你看

加一句：「改好之後告訴我要看哪裡」。 它會告訴你去首頁還是設定頁看，你自己確認過才點「上線」。

不確定就問

它不會嫌問題笨。可以直接問：

  • 「這個檔案在做什麼？」
  • 「我改這一行會影響到什麼？」
  • 「這樣改會不會動到小孩的紀錄？」

兩個人一起改的規矩

檔案已經拆開了，所以大部分時候你們不會撞在一起。抓最新版的事「開發」會自己做， 所以只剩兩條要守：

  1. 同一天不要兩個人改同一個檔案。先說一聲「我今天動 content.js」。
  2. 改完當天就送出，不要累積好幾天。改得越少，出問題越好找。
如果「送出」說你跟 Jessie 改到同一個地方，不要自己試著修—— 你的修改都還在，什麼都沒丟。把畫面截圖傳給他，三分鐘就解決。

卡住的時候

狀況怎麼辦
畫面一片空白通常是漏了一個括號或引號。點「還原」，重改一次
改了沒反應檔案存檔了嗎？瀏覽器按 ⌘R 了嗎？手機上要下拉重新整理
手機上沒更新已經加到主畫面的話，要把 app 完全關掉再開
越改越亂點「還原」。這就是它存在的理由
送出後多久會上線要等 Jessie 合併。合併後約一分鐘
手機掃 QR 打不開手機跟電腦要連同一個 Wi-Fi。還是不行就在手機瀏覽器直接打畫面上那個網址
不知道改哪裡問 Claude Code：「我想改 ⋯⋯，要動哪個檔案？」
某一關跳出「這一關出了問題」這是正常的保護，不是壞掉。 把上面那行小字截圖給 Claude Code 看，它會告訴你改錯哪裡
改壞一關不會把整個 app 弄死。出問題的那一關會自己跳出提示、 按「跳過這一關」就接著做下一關。所以你可以放心改——改壞了，畫面會直接告訴你原因。

紀錄跟程式是兩回事

「還原」只會還原程式，不會動到小孩的練習紀錄。這兩件事完全分開：

存在哪怎麼救回來
程式（你改的東西）電腦上的檔案點「還原」
練習紀錄（天數、難度、校準）手機／瀏覽器裡面設定裡的「匯出備份」

所以：每次回診前，在小孩的手機上匯出一份備份，用 AirDrop 傳到電腦存起來。 換手機或手機壞掉的時候，從設定裡「讀回備份」就全部回來了。

你在電腦上測試用的紀錄，跟小孩手機上的紀錄是兩份、互不影響。 你在電腦上怎麼亂按都不會弄亂她的紀錄。

關於這個 app 本身

有兩件事在改任何東西之前要知道，因為它們會影響你的判斷：

  • 視標大小是這個 app 唯一真正重要的變數。其他都是為了讓小孩願意每天打開。 所以「好玩」和「有效」不衝突——不好玩她就不練，不練就沒有效。
  • 這不是醫療器材，也不能治療疾病。所以文案裡絕對不要出現「治療」「矯正」「改善視力」 這類字眼。它只是把練習時間記下來、自動調整難度。這一點之後要上架 App Store 時會被審查。

之後要上架 App Store

那是後面的事，而且不影響你現在做的任何事情——現在改的東西，到時候原封不動會變成 app 裡面的內容。 你不用為了上架改變做法。
